# 山水S酒店 · 婚宴菜单系统 使用说明

> 适用版本：v6（设计稿）
> 核心设计原则：**系统代码（默认版本）与酒店数据（独立 JSON）彻底分离**。
> 一套系统可以给任意多家酒店用，每家酒店的数据互不影响。

---

## 一、三个概念先分清

| 概念 | 是什么 | 存在哪里 |
|---|---|---|
| **默认系统（代码）** | index.html + assets/ 这套前端程序，不含任何具体酒店的数据 | GitHub / 云端部署 |
| **本酒店数据（JSON）** | 你这家店的菜品库、套餐、价格、图片裁切位置 | 浏览器本地 + 一份导出的 JSON 备份文件 |
| **展示设备** | 平板 / 手机上打开的网页 | 客人看到的界面 |

**关键点**：代码是"空壳"，数据是"填进去的内容"。换一家酒店，只换 JSON，不动代码。

---

## 二、首次使用 / 换设备：如何拿到你的数据

你有两种方式把"真实菜单"装进系统：

### 方式 A：导入配置 JSON（推荐，最稳妥）

1. 在**原来已经在用的设备**上打开系统 → 进入「管理」→ 点右上角 **⚙ 设置**
2. 点 **导出配置（JSON）** → 下载一个 `.json` 文件（这就是你全部菜品的完整备份）
3. 把这份 JSON 传到新设备（微信文件传输 / U 盘 / 邮件都行）
4. 在新设备的系统里 →「管理」→ **⚙ 设置** → **导入配置（JSON）** → 选中那份文件
5. 全部菜品、套餐、价格、图片瞬间恢复

> 这份 JSON 就是你酒店的"数据保险单"，**务必定期导出保存一份**（比如存在电脑/网盘）。

### 方式 B：从空白开始录入

如果是一套全新环境，直接进「管理」→「菜品库」→ **+ 新增菜品** 逐个录入即可。

---

## 三、自动识别（设计中的体验）

规划中的逻辑：**系统启动时如果发现本设备没有任何数据，会自动弹出引导**，而不是显示一个空荡荡的界面：

- 选项 1：**导入已有配置**（点一下选 JSON 文件）
- 选项 2：**使用示例数据开始**（先看看默认样子，之后再替换）
- 选项 3：**从空白新建**

这样即使你忘了导入，也不会对着空白界面发懵。

---

## 四、多人 / 多酒店协作建议

- **每家酒店 = 一份独立 JSON**。不要用同一份 JSON 给两家店，否则改动会串。
- 想给新酒店部署：克隆代码 → 部署 → 导入该酒店自己的 JSON。
- 改动菜品后，记得**重新导出 JSON** 覆盖旧备份（JSON 不会自动同步，需手动导出）。

---

## 五、常见疑问

**Q：我把代码上传到 GitHub，数据也在里面吗？**
A：不在。GitHub 只存代码（默认系统）。你的真实菜品在浏览器本地 + 你导出的 JSON 文件里。所以换电脑后必须"导入 JSON"才能恢复真实菜单。

**Q：云端部署挂了怎么办？**
A：代码在 GitHub（保险），数据在 JSON 文件（另一份保险）。换台电脑重新部署 + 导入 JSON 即可复活。

**Q：图片会丢吗？**
A：菜品图片以 base64 形式存在数据里，跟着 JSON 一起导出/导入，不会丢。单张图会被压缩到约 60–140KB，足够展示。

**Q：数据存在哪里，安全吗？**
A：存在浏览器的 localStorage（按设备隔离）。它不上传任何服务器，纯本地。代价是：清了浏览器缓存 / 换了设备，就需要重新导入 JSON。
