# UI 设计规范

> 最终确认版，2026-09-06 生效。本文整体替代旧 UI 1–16 节及原第 17 节提案。旧固定左右分栏、双上滑、强制暗色、高频 PIN 均不构成开发约束。令牌是实施基线，实际视觉/设备验收尚待进行；阶段 1 只做能力验证界面。

### 1 设计方向与原则

以“酒店专业感、东方克制、平板销售效率”为方向。保留菜品真实摄影和中文排版的品牌辨识，弱化大面积红金、叠加玻璃、印章和繁复边框。展示、销售操作、运营分别布局，共用控件语义；不再把旧左右分栏、封面和旧卡片视为不可修改约束。

三种空间：展示页安静、图片与菜名优先；销售页高效、版本和下一步清晰；运营页高密度、方便批量维护。内部字段在受限展示投影中不存在，不只是隐藏按钮。该状态不是“客户登录后首页”。

### 2 设计令牌

以下为统一实施基线，实施时在目标平板验证对比度与中文字体，不声称已经完成视觉验收。

| 类别 | 建议 | 使用 |
| --- | --- | --- |
| 画布/表面/主文字 | #F6F3ED / #FFFFFF / #282621 | 暖白纸感与清晰正文 |
| 次文字/边框 | #625C53 / #DCD6CB | 高于装饰色的信息可读性 |
| 品牌主色 | #813C33 | 小面积主按钮、当前选择，不铺满整个工作台 |
| 装饰金 | #B29764 | 细线或眉题，不作小字正文 |
| 状态色 | success #2F6C47、warning #8A5B10、danger #A32626、focus #245AC4 | 图标+文字，避免仅靠颜色 |
| 字体 | 本地中文衬线用于品牌/菜单标题；本地中文无衬线用于正文/数字 | 仅少量字重，许可与缺字必须验收；不要求所有内容衬线 |
| 字号 | 标题 28/36；价格 32/40；分区 20/28；工作正文 16/24；辅助 14/20 | 正式操作不使用 11px 小字；大字模式用重排 |
| 间距/圆角 | 4px 网格，12/16/24/32 常用；控件 8px，卡片 12px，抽屉 16px | 共用组件定义，减少局部覆盖 |
| 触控 | 主要操作 48px 高，最小有效目标 48×48px，间隔 8px | 屏幕需按逻辑尺寸验证，不以截图像素推断 |
| 动效 | 输入反馈 ≤100ms；简单淡入 120–180ms；抽屉 220ms | 无自动轮播/超时跳页；减少动效时取消位移 |

首版只验收浅色品牌主题，深色工作区后置；导出始终固定浅色。旧 UI 对暗色、图片加工等要求不能被默认为本次新增范围。仅保存用户选择的裁剪，不自动改变菜品色彩或器皿。

### 3 关键页面结构与操作预算

| 页面 | 初步结构 | 高频路径 | 空态/异常 |
| --- | --- | --- | --- |
| 今日 | 顶部当前销售与“快速接待”，下方最近洽谈、待回价、待跟进；不放销售业绩大屏 | 1 次点按续接；新接待不填客户表 | 无记录直接开始；明确本地保存/备份状态 |
| 标准菜单 | 宴席由销售选择；套餐采用顶部可横滚标签，主区三列菜图；当前菜单名及每桌价持续可见 | 1 次切套餐；1 次看详情；“以此定制”常驻销售操作栏 | 无菜单由销售进入运营处理；受限态无运营入口 |
| 套餐比较 | 最多两列，上部标准价与差额，下部 2–4 个审核后的升级项，相同项折叠 | 选择第二套餐后即比较，无确认页 | 未配置配对时显示增减项；不伪造“更高级”解释 |
| 定制工作台 | 中部有序菜品行，右侧窄报价区可收起；顶部客户标签/方案/V号/保存状态；底部下一步动作 | 换菜→搜索→选中；新增共用选菜器；Undo 常驻 | 空方案可加菜；保存失败保留行和输入，禁止显示已保存 |
| 换菜抽屉 | 搜索在顶、结果网格在下；“使用输入菜名作为临时菜”靠近搜索结果 | 临时菜不退出当前方案；分类默认继承原菜 | 无结果仍有自由输入；重复菜给行内提示，已有条目可定位 |
| 报价区 | 突出当前对客报价（元/桌），下方有效性提示；“录入厨房回价”和“查看历史”为次级操作 | 厨房仅回复金额也能直接录入，无需编号 | 改菜后旧价标过期，资料变化不影响有效性 |
| 客户详情 | 称呼/本次宴会资料，最近方案，时间线；资料后补 | 点历史报价即可重开；“继续修改”生成新草稿 | 无电话/日期不是错误；同号客户仅提示不自动合并 |
| 版本查看 | 顶部版本/用途/时间/操作者，正文只读；可选比较两版 | 保留一个“继续修改”入口 | 冲突分支并列，不隐藏丢弃其中一个 |
| 导出预览 | 上部受众标题，客户版选“小票/有图”，尺寸格式次级；正文预览与页数；一个生成按钮 | 记住模板偏好；不可沿用上次厨房受众作为客户默认 | 字体/图片加载中保持预览；失败可重试、无成功 Toast |
| 套餐编排 | 宴席/套餐列表+菜品行+库选菜抽屉；预览为当前内容投影 | 批量添加、跨套餐复制、可见排序手柄/上下移动 | 引用缺失集中列出；未保存编辑可恢复 |
| 内容检查 | 按临时菜、缺图、无效引用、停用、重复候选分组 | 行内处理；批量操作前给影响摘要 | 空态“暂无待处理内容”，不展示虚构分数 |

### 4 受限展示状态机

```text
销售工作态 → 保存白名单成功 → 受限展示态
受限展示态 → 菜品详情 → 返回授权套餐
受限展示态 → 取回操作 → 销售恢复验证 → 原销售上下文
任何启动/恢复 → 先读取持久化状态 → 继续受限态或解锁页
状态损坏/范围失效 → 中性锁定空态 → 销售解锁后恢复
```

进入可见“交给客户浏览”，默认当前宴席和当前套餐；扩大范围使用同一个轻量选择面板，不增加多轮确认。取回提供会话内低摩擦恢复候选：持续按住销售入口后执行明确的滑动，或取回入口接设备凭证/生物识别。阶段 1 比较连续 10 次交接的耗时、误触和返回边界，不锁定高频 PIN。会话内操作门槛用于防误入，不能宣称身份认证；冷启动、过期会话或切换人员时再验证身份。没有实际设备凭证时不得用假验证冒充安全。

白名单包含具体套餐修订/正式方案版本，不是仅宴席 ID；所有数据查询、搜索、详情前后、恢复和内部链接都受同一范围检查。进入期间暂停公共菜单版本切换，不能因为同步更新让客户看到新套餐。失效时不自动扩展到全部套餐。

| 情况 | 预期行为 |
| --- | --- |
| Android 返回/预测性返回手势 | 先关键盘、再关详情/比较；受限根页不得返回销售首页；手势预览不提前露内部页 |
| Home/最近任务/外部应用 | 本应用内部数据保持锁定；普通 APK 不保证控制外部应用，受管设备需求另议 |
| 旋转/分屏/窗口改变 | 保持白名单、选中套餐和位置；布局重排不重置身份 |
| 进程被杀/异常/重新打开 | 持久化范围先恢复，启动中性画面，不闪现厨房报价或客户列表 |
| 销售输入解锁失败 | 留在受限状态，限速重试；不触发菜单重建 |
| 客户请求改菜 | 口头沟通，销售取回恢复销售工作态后修改；客户端无换菜入口 |

### 5 三种独立输出视觉

| 输出 | 排版目标 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| 厨房询价 | 编号/版本/基础套餐在顶，变更优先，高对比文字列表；完整菜单可续页 | 原菜划线、改为、新增、删除、厨房备注、核价条件；清楚标“待核价” | 客户电话、销售议价记录、利润、把询价写成备餐指令 |
| 客户小票 | 竖向餐单、中文菜名为主、品牌和套餐价明确、精细分隔、克制留白 | 最终菜品、明确对客备注、选定对客价格，可选客户称呼 | 内部状态、原菜、删除线、厨房价、空白备注占位 |
| 客户有图 | 宴会提案菜单册，A4 可分页；图片不为强塞单页缩到不可辨识 | 4:3 图、菜名、需要时英文、菜单总价与品牌 | 修改轨迹、内部字段、自动改造菜图 |

小票可借鉴当前 750px 长图的纸张边缘和分隔语言，但新模板独立实现；不用“更新版”“原始版”当客户菜单主标题。客户菜单为“宴席菜单/正式报价菜单”，技术版本只以简洁编号置于次要位置；厨房明确标询价编号。资料未填时整行省略，不打印“—/贵宾”占位。

### 6 组件、状态与无障碍

首批组件：AppBar、PackageSelector、DishCard、DishRow、DishPicker、PriceField、SaveStatus、VersionBadge、ChangeSummary、UndoBar、Drawer、Dialog、ExportPreview、EmptyState、ErrorBanner。每个组件必须有可访问名称、焦点、禁用/忙碌、空/失败状态；业务模块不访问组件内部 DOM。

可撤销增删换菜不弹确认；不可恢复清空、覆盖导入、客户确认留底等少数高影响动作才解释后果。返回优先关闭当前一层，不一次关闭所有弹窗；焦点回到触发器。输入过程中关闭抽屉可保留未提交编辑草稿，不要求用户反复确认。

表单标签不可仅靠 placeholder；金额支持完整输入和加减快捷操作，确认前展示实际结果；不把非法输入按 0 保存。触摸拖动有明确手柄及上下移动替代；条目超长允许多行，不压小字号。

1280×800 为主；1024×768、768×1024 竖屏把报价区收为底部可展开面板；390×844 使用单列、固定操作区。键盘出现时活动输入和当前动作可见，不强制锁横屏。放大与辅助字体不能被 viewport 禁用；错误与保存状态用 live region，受限浏览只给不含内部内容的错误提示。

### 7 验证场景与三轮评审

视觉基准覆盖：今日、标准菜单、两套餐比较、菜品详情、定制、临时菜空搜索、报价、历史版、受限空态、运营缺图、导出三模板首尾页。包含最长中文/英文、无图、1/16/40/100 道菜、离线、保存失败、生成取消、字体回退、旋转及键盘遮挡。

销售评审：快速接待无需填表；反复拿回平板不要求每次输入 PIN；1–2 道换菜没有原因弹窗；客户慢看不自动跳走。由此取消旧双手势与超时返回。

产品评审：今日和客户详情能恢复上下文；时间线记录看过/比较/报价的事实，不推断意向；导出一级动作无需单独文件管理系统。由此合并导航和限制模板数量。

工程评审：受限展示没有内部数据，版本不可变，持久化先于成功提示，异步导出读取冻结任务；长内容先分页，失败不静默缺页。由此先建领域与数据投影，再做视觉页面。

上述为本轮内部推演结果，真实销售与厨房评审安排在试点门禁，不将推演等同实际可用性测试。

### 8. 报价与留底交互约束

厨房回价 2899 → 销售设定对客 2999 后，日常只突出 2999 元/桌；历史抽屉按“厨房参考/对客调整”及时间显示两笔来源。禁止三列价格常驻、利润/差价仪表盘或成交管理入口。桌数与日期收在宴会资料中，修改时不得弹重新核价。

“客户确认方案”只在销售明确记录客户决定后形成留底；确认前展示最终菜单和当前每桌报价摘要，可沿用已知资料，不要求补电话、桌数等才接待。留底页只读，继续修改或资料更正建立新修订。客户模板不得出现内部价格、换菜痕迹或财务成交状态。
